## ✨ 核心功能

### 任務管理
- ✅ 創建、編輯、刪除、複製任務
- 🏷️ 標籤系統（分類和快速搜尋）
- 📅 日期設定（具體日期、📥 暫存區、不限期）
- 📥 **暫存區** — 放未規劃時間/細節的任務，不列入任何篩選與統計，只在首頁最上方可見，可用快捷鈕或拖曳隨時排入某天
- 🕐 **當天時刻 HH:MM** — 任務可指定當天時刻，一天內依時刻由早到晚自動排序（未指定時刻者排在最前）；拖曳到某任務下方會依「前一項時刻＋前一項預計耗時」自動推算時刻
- ⚡ 快速日期選擇（今天、明天、後天、下週一～日）
- ⏱️ Block 時間估計（10 分鐘內、30 分鐘/1 block、多 blocks、非連續）
- 📊 任務統計（完成率、時間節省/延遲分析）
- 📝 下一步建議（完成任務時記錄反思與計劃）

### 分類系統
- 💼 **事業**（Career - 工作/學習）
- ⚡ **充電活動**（Recharge - 休閒/運動）
- 🏠 **生活必須**（Life - 日常事務）
- 🔍 **復盤**（Review - 回顧/反思）

### 視圖和過濾
- 📊 所有任務（依到期日分區：📥 暫存區／逾期／今天／明天／後天／更久以後，今天／明天／後天分區即時顯示已預定／完成／剩餘時數）
- 按分類和標籤過濾（暫存區任務不列入任何分類/標籤/群組篩選，也不計入統計卡）

### 排序功能
- 拖曳排序（Drag & Drop）
- 固定順序
- 📌 **任務釘選** - 置頂／置底，永遠維持在該天任務清單最上/最下，重新安排天數後仍維持
- 時間追蹤（實際完成時間 vs 預計時間）

### 迴圈群組
- 定時迴圈任務（自訂間隔天數 + 結束日期 / 重複次數）
- 任務群組管理（群組內拖曳排序、自動日期計算）
- 完成後自動建立下次任務，並標示「已完成N次」
- 🔁 **重複次數優先** — 設有「重複次數」時，以「做滿 N 次」為終止條件；任務被逾期順延（重新安排到今天／自動建立下一次／群組重算）時，「預定結束日期」依「本次日期＋剩餘次數×間隔」自動順延，確保不會在做滿次數前提前結束

### 完成時間分析
- **一般**：套用預計時間
- **⏩ 節省**：預計時間 - 實際時間（賺得時間）
- **⚠️ 延遲**：實際時間 - 預計時間（超支時間）
- **⏭️ 超前**：未到截止日期即完成
- **逾期重新安排**：逾期任務用「重新安排到今天」時，記為原定日期的時間損失（負值時間收支），但**不增加**原定日期的預定時間（改期後新日期會再計一次，避免重複）；拖曳或直接改日期則不計入

### 雲端同步（v6.3 起，取代舊的「同步資料夾」）
- ☁️ **自動雙向同步** - 資料同步到你自己的 **GitHub 私有 repo**（單一 `state.json`），桌面（`file://`）與手機（Android PWA）皆可，不必再手動匯出/搬檔/匯入
- 🔀 **自動合併，不是整檔覆蓋** - 兩台各自修改**不同任務**不會互相蓋掉，自動合併不打擾；刪除以 `deletedTasks` 標記傳播，標籤與逾期損失紀錄取聯集
- ⚠️ **資料衝突先詢問**（v6.3.3 起）- 同一個任務「兩台都改過、且改得不一樣」時不再靜默取較晚者，而是跳出視窗列出差異，讓你選：🔀 交叉補充／🆕 完全取新版／☁️ 以雲端為準／💻 以本機為準（只作用在衝突的任務，其餘照常合併）；也可「稍後再說」。匯入備份檔遇到衝突時共用同一個視窗
- ⏱️ **觸發時機** - 開啟 App、回到前景/視窗聚焦、恢復連線、前景每 60 秒輪詢，以及每次修改後防抖 5 秒自動上傳；離線時照常使用，恢復連線後自動補上傳
- 📱 **新裝置免打字** - 「雲端同步設定」可產生「新裝置設定連結」，在手機開啟即自動帶入設定（連結含 Token，僅限自用，用完即刪）
- 🕘 **可回復** - 每次同步是一個 git commit；套用遠端資料前，本機會先留一份快照（`todoPreSyncBackup`）
- 💾 **備份檔** - 「匯出備份檔／匯入備份檔（合併）」桌面與手機通用，作為離線保底，也可匯入 v6.2 以前的 `todomaster-backup-*.json`
- 📁 **備份資料夾（v6.3.4 起）** - 匯出、匯入前**一律先詢問要用哪個資料夾，不會自動下載**：桌面 Chrome／Edge 跳出資料夾選取視窗（匯出＝寫入該資料夾；匯入＝列出資料夾內的 `.json` 由新到舊供選擇，也可改選單一檔案）；手機、Firefox、Safari 無法指定資料夾，匯出先跳說明確認才下載到瀏覽器預設位置，匯入直接開系統檔案選擇器
- 設定步驟見下方「☁️ 雲端同步設定」

### 其他功能
- 📦 **壓縮任務** - 整理過期或已完成任務；完成超過 30 天的任務與逾期損失記錄會在開 App 時自動清除（`purgeOldData()`）
- 🧹 **整理重複任務**（側邊欄「視圖」區，v6.3.2 起）- 找出同一個迴圈／群組任務同時存在多份「未完成」副本（例如兩台裝置各自完成、或新舊資料合併後重複），列出預覽，只保留日期最晚的一份，較早且已逾期（或完全重複）的副本預設勾選刪除；刪除會經雲端同步傳到其他裝置。規則見版本歷史 v6.3.2
- 🗑️ **清理已完成** - 批次刪除已完成任務
- 📊 **時間統計** - 匯總完成時間與效率分析

### UI/UX
- 🌙 深色主題（低眼疲勞配色）
- 📱 **響應式設計** - 完全適配手機（768px 斷點）

## ☁️ 雲端同步設定

只需設定一次（約 5 分鐘）。資料放在**你自己帳號下的私有 repo**，App 用 GitHub API 讀寫；App 會拒絕連到公開 repo。

### 步驟 A：建立私有資料 repo
1. 登入 GitHub → 右上 **＋ → New repository**
2. Repository name：`todomaster-data`；可見性選 **Private**
3. **勾選「Add a README file」**（讓 repo 非空，最穩妥）→ **Create repository**

> ⚠️ 不要用 `todomaster` 這個 repo：它是公開的（GitHub Pages），任務資料會被任何人看到。

### 步驟 B：建立 Fine-grained Token（只授權這一個 repo）
1. 右上頭像 → **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**
2. Token name：`TodoMaster Sync`；Expiration：**1 year**（到期前需更換，App 會顯示「Token 失效」）
3. Resource owner：你自己；Repository access：**Only select repositories** → 只選 `todomaster-data`
4. Permissions → Repository permissions → **Contents：Read and write**（Metadata: Read 會自動帶入）
5. **Generate token** → 立即複製（只顯示一次）

### 步驟 C：第一台裝置（請用「資料最新、最完整」的那台）
開啟 `TodoMaster.html` → 側邊欄「☁️ 雲端同步 → ⚙️ 雲端同步設定」→ 填入帳號、`todomaster-data`、貼上 Token → **測試並儲存**。連線成功後本機資料會自動上傳。

### 步驟 D：其他裝置（例如 Android）
- 先確認最新版已部署到 GitHub Pages（`git push origin master`）。v6.3.1 起 HTML 為網路優先，手機開啟 App 會自動換上新版；若仍是舊畫面，見下方 FAQ「手機顯示舊版」
- 在第一台裝置的「雲端同步設定」底部按 **📋 複製連結**，用你自己的管道傳到手機（如 LINE 記事本/Keep），在手機開啟連結 → 確認對話框 → 自動設定並同步。**用完請刪除該則訊息**（連結含 Token）
- 也可以在手機的設定畫面手動貼上 Token

### 狀態列說明
`☁️ 已同步 · N 分鐘前`／`⏳ 待上傳變更`／`⚠️ 離線，恢復連線後自動同步`／`❌ Token 失效…`（到「雲端同步設定」重新貼 Token）。「🔄 立即同步」可隨時手動觸發。

### 資料格式與回復
- `state.json`：`{ schema: 2, tasks, tags, overdueLossLog, deletedTasks, … }`；每筆任務多了 `updatedAt`／`orderAt`（毫秒時間戳，內容與排序各自比對）
- 誤操作或想回到某個時間點：到 `todomaster-data` 的 **commits** 歷史還原 `state.json`，再於 App 按「🔄 立即同步」
- 本機保底：開發者主控台執行 `app.restorePreSyncBackup()` 可還原「套用遠端資料前」的本機快照（只留最近一份）
- 同一任務在兩台裝置**都修改過且內容不同**時（衝突），會跳出視窗讓你選處理方式（見版本歷史 v6.3.3）；沒有重疊的修改自動合併
- 新增 `localStorage` 鍵 `todoSyncBase`：基準快照（上次同步後雙方一致的任務內容），用來判斷「哪些任務兩邊都改過」

### v6.3.4 (2026-09-24) - 新增備份資料夾：匯出／匯入前先詢問資料夾
- ✅ **匯出備份檔不再直接下載**：`exportBackupFile()` 改為先詢問資料夾。
  - **桌面 Chrome／Edge（有 `showDirectoryPicker`）**：跳出資料夾選取視窗，選好後把 `todomaster-backup-<日期時間>.json` 直接寫進該資料夾，提示「✅ 已備份到「資料夾名」：檔名」。**每次都問**（不保存資料夾授權）；選取視窗的 `id` 只讓對話框停在上次用過的位置。選完資料夾才取資料，選取期間同步進來的變更也會包含在備份裡
  - **其他瀏覽器（手機、Firefox、Safari，無法由 App 指定資料夾）**：先跳 `confirm()` 說明「會下載到瀏覽器預設下載位置」，同意才下載，取消就什麼都不做

- ✅ **匯入備份檔先問來源**：桌面 Chrome／Edge 按「匯入備份檔」先跳 `#backupImportModal`，兩個入口：
  - 📁 **選擇備份資料夾**：選好後列出資料夾內所有 `.json`（新到舊、附修改時間與大小，預設選最新一份；子資料夾與非 `.json` 不列），選一個按「載入選取的備份」。空資料夾會提示並停用載入鈕

### v6.3.3 (2026-09-24) - 處理版本衝突：固定 id 根治重複、衝突先詢問
- ✅ **迴圈任務的「下一次」改用固定 id（根治重複）**：新欄位 `seriesId`（系列根任務 id，舊任務沒有就以自己的 id 當根），第 n 次的 id 固定為 `${seriesId}~${n}`（純函式 `nextRecurringId()`）。兩台裝置各自完成同一個任務會算出**同一個 id**，合併時自然收斂成一份；`createNextRecurringTask()` 若發現該 id 已存在就不再建立（單機「取消完成再完成」經完成時間視窗／Block 全完成／非連續任務三條沒有防重的路徑，也不會再多生一份）。`duplicateTask()` 複製時清除 `seriesId`（副本是新系列，避免 id 互撞）。舊任務不需遷移；既有的重複份仍用「🧹 整理重複任務」清
- ✅ **資料衝突先詢問，不再靜默取較晚者**：三向比對——以「上次同步後雙方一致的內容」（`todoSyncBase` 基準快照）為基準，同一任務本機與雲端**都與基準不同且彼此不同**才算衝突（`detectConflicts()`）：`edit`（兩邊都改）、`add`（基準沒有、兩邊各自有但內容不同：首次連線兩邊都有資料，或固定 id 的「下一次」兩台算出不同內容）、`remote-deleted`／`local-deleted`（一邊刪除、另一邊修改）。**不算衝突**（照舊自動合併）：沒重疊的修改、兩邊內容相同、只有排序不同、被自動清除的舊資料
- ✅ **處理方式（全域選一種，只套用在衝突任務）**：🔀 **交叉補充**（預設，欄位層級三向合併：各改不同欄位全部保留、同欄兩邊都改取較晚者、`recurring` 逐子欄位合併、`tags` 雙方新增都留／任一方移除就移除、一邊刪除一邊修改則保留任務；無基準時較新者為準、空值由另一邊補上）／🆕 **完全取新版**（整筆用最後修改的那份）／☁️ **以雲端為準**／💻 **以本機為準**；另有「稍後再說」（本輪不套用不推送，10 分鐘內自動觸發不再彈出，手動「立即同步」會再問）。決定會蓋新的 `updatedAt`，避免下一輪合併又被較新的一邊蓋回去；套用前先留本機快照

  - 清舊快取只動 `todomaster-` 前綴（快取空間是整個網域共用，舊寫法會刪掉同網域其他專案的快取）

## 維護原則

1. **單一文件** - 所有代碼在 `TodoMaster.html` 中
2. **零依賴** - 純 HTML5 + JavaScript，無外部庫
3. **本地存儲** - 所有數據在 `localStorage`，無自建伺服器（雲端同步只是選用的副本）
4. **隱私優先** - 預設不上傳任何地方；啟用雲端同步後，資料只會上傳到使用者自己的 GitHub **私有** repo（App 拒絕公開 repo），Token 僅存於本機 `localStorage`
5. **手機友好** - 響應式設計，768px 斷點

## 限制與注意

- **localStorage 限制**：約 5-10MB，支援 1000+ 個任務
- **隱私模式**：隱身模式無法持久化數據
- **雲端同步**：需連網並使用自己的 GitHub 私有 repo + Fine-grained Token（最長 1 年到期）；非即時推播，另一台的修改會在其開啟／回到前景／最多約 60 秒內出現；同一任務兩台都改過且內容不同時會先詢問處理方式；請避免同一台裝置同時開多個分頁編輯
- **舊瀏覽器**：需支援 ES6 的現代瀏覽器

## ❓ 常見問題

**Q: 修改 HTML 後，需要上傳到伺服器嗎？**  
A: 不需要。使用者直接打開本地 TodoMaster.html 即可，所有數據存在瀏覽器本地。（要讓 Android PWA 取得新版才需 `git push origin master` 部署到 GitHub Pages。）

**Q: 如何跨設備同步資料？**  
A: 使用「☁️ 雲端同步」：一次性建立私有 repo `todomaster-data` 與 Fine-grained Token，之後各裝置自動雙向合併，不必手動匯出/匯入。步驟見上方「☁️ 雲端同步設定」。

**Q: 手機沒有顯示我在電腦做的修改？**  
A: 側邊欄狀態列會顯示同步狀態；點「🔄 立即同步」。若顯示「Token 失效」請重新貼 Token；若頂欄版本號不是最新，見下一題。

**Q: 同步時跳出「兩台裝置的資料有衝突」，該怎麼選？**  
A: 視窗會列出哪些任務、哪些欄位兩邊不一樣（本機｜雲端）。不確定就選預設的「🔀 交叉補充」——兩邊的修改盡量都留下（各改不同欄位就全留、同一欄位取較晚修改者、一邊刪除一邊修改則保留任務）。想直接用最後修改的整份選「🆕 完全取新版」；確定某一邊才是對的選「☁️ 以雲端為準」或「💻 以本機為準」。還沒決定可按「稍後再說」（資料完全不動，10 分鐘內不再彈出，按「🔄 立即同步」會再問）。沒有衝突的修改（兩台改的是不同任務）一律自動合併，不受這個選擇影響。

**Q: 同一個重複任務出現兩份（其中一份是逾期的舊副本）怎麼辦？**  
A: 側邊欄「視圖」→「🧹 整理重複任務」。先按「🔄 立即同步」讓各裝置資料一致，再開這個功能：預覽會列出每個重複任務要保留哪一份、哪些較早副本會刪（逾期或完全重複者預設勾選），確認後刪除並自動同步到其他裝置，只需在一台裝置操作。

**Q: 手機顯示舊版（頂欄版本號不是最新）怎麼辦？**  
A: 先確認電腦已 `git push origin master`，且 `https://gjpswhaod.github.io/todomaster/TodoMaster.html` 在電腦瀏覽器顯示最新版。v6.3.1 起，開啟 App 會自動偵測並換上新版（畫面可能自動重新載入一次）：打開 App、等約 10 秒；沒變就完全關閉 PWA 再開一次。**不要**用「清除網站資料」——會清掉手機上的任務與同步設定（要清之前務必先按「🔄 立即同步」）。從 v6.3 以前的版本（Service Worker 為 cache-first、可能已被汙染）升級，只要部署 v6.3.1 之後開一次 App 即可自動修復。

**Q: 匯出／匯入備份檔時會問我要用哪個資料夾嗎？在「下載」「文件」「桌面」選不了？**  
A: v6.3.4 起匯出、匯入前一律先詢問，不會自動下載。桌面 Chrome／Edge：匯出會跳資料夾選取視窗，備份檔直接寫進你選的資料夾（第一次用建議新增一個專用資料夾，例如 `TodoMaster備份`；下次選取視窗會停在同一位置）；瀏覽器出現「編輯此資料夾的檔案？」請選允許。Chrome／Edge 不允許直接選「文件」「下載」「桌面」這幾個資料夾**本身**，要選它底下的子資料夾。匯入時若備份放在那些位置（例如 v6.3 以前匯出的檔案在「下載」），在匯入視窗改用「📄 直接選擇單一備份檔」。手機、Firefox、Safari 無法讓 App 指定資料夾：匯出會先跳說明確認，同意後下載到瀏覽器的預設位置（可在瀏覽器的下載設定開啟「儲存前詢問位置」）；匯入直接開系統檔案選擇器。

**Q: 備份文件要保留多久？**  
A: 建議保留最近 10 個版本，定期清理過期備份。

**Q: 如何確保不會丟失使用者的任務數據？**  
A: 新版本需完全相容舊版本的 localStorage 格式，做好數據遷移測試。
